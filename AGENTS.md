# Repository Guidelines

## Structure

Tokenx is a Rust workspace with Bun-managed JavaScript packages.

- `crates/tokenx-engine/`: parsing, scanning, aggregation, pricing, and session readers.
- `crates/tokenx/`: CLI, TUI, subscriptions, and integration tests.
- `packages/tokenx/`: TypeScript npm launcher.
- `packages/tokenx-*`: native npm package manifests.
- `docs/`: user documentation, verified client facts, and ADRs.

Prefer existing module boundaries and domain names such as `client`, `provider`, `model_id`, and `session`. Preserve raw model observations for diagnostics, then use canonical model IDs for grouping and pricing.

## Commands

```bash
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-features -- -D warnings
cargo test --locked --workspace --all-features
bun install --frozen-lockfile
bun run build
bun run test:release-tooling
bun run test:launchers
```

Pass `--no-spinner` whenever an automated command runs Tokenx, unless spinner behavior is under test.

## Tests

Keep pure-logic tests near their implementation and put CLI/session integration tests under the relevant crate's `tests/` directory. Use temporary directories and synthetic fixtures, never developer-local data paths. Scale coverage with the behavior and blast radius of the change.

## Documentation and ADRs

Keep `README.md` as the concise product entry page and synchronize `README.zh-cn.md` when it changes. Put detailed command, client, pricing, configuration, release, and development material under `docs/`.

Read the owning ADR before changing an established contract. Record explicit breaking decisions or major design disagreements in the next sequential `docs/adr/xxxx-title.md`, focusing on the decision, rationale, and important trade-offs.

## Data Pipeline Invariants

- Resolve `--client` or `defaultClients` once at TUI startup into an immutable client universe. Without either, use the complete accepted local catalog.
- Treat Clients and Group By as projections of the installed generation. They must not scan inputs, write cache state, reset refresh clocks, or persist picker selection; see ADR 0007.
- Scan only for a stale or missing startup generation, automatic refresh, or explicit manual refresh. Acquisition stays in the background, and projection controls remain disabled until the first generation exists.
- Preserve the installed generation when a warm refresh fails and expose a degraded diagnostic. A cold failure has no generation and remains an explicit error.

## No-Silent-Fallback Discipline

Read `docs/adr/0001-no-silent-fallback.md` before classifying behavior as fallback. The policy prohibits hidden failure and invented success; it does not prohibit documented normalization, reconciliation, projections, or authority-priority rules.

Do not remove behavior because an identifier says `fallback`. Identify the authoritative contract and a concrete masked failure first. Any ADR 0001 behavior change needs a focused regression test.

Provider attribution is optional metadata. Retain valid model/token records, infer centrally, and use `unknown` when inference fails. Only a documented ownership, filtering, or deduplication field may gate eligibility.

## Commits and Pull Requests

Use conventional commit and PR titles: `<type>(<scope>): <what changed and why>`. Keep changes atomic and describe the actual technical change. Do not use internal review labels or vague titles.

Before committing, inspect the effective Git identity and remotes. Do not set repository-local identity to another contributor or commit under a worker/test identity. Use squash merge for pull requests unless the user explicitly requests another strategy.

## Release Safety

The npm package family is `@juya-ai/tokenx` plus the supported `@juya-ai/tokenx-*` native packages. Do not publish packages, run the publish workflow, create tags, or create GitHub Releases unless the user explicitly requests that release operation.

Release bumps are exact version-only commits generated by `bun run release:bump -- <version>`. They may change only `Cargo.toml`, `Cargo.lock`, `bun.lock`, and the release npm manifests. Regenerate the canonical third-party notice and verify package legal metadata after dependency changes with:

```bash
bun run licenses:generate
bash scripts/check-npm-package-files.sh
```
